# จับรางวัล · 幸运抽奖 PWA

泰中双语抽奖程序。Excel / CSV / PDF 导入名单,分等级依次开奖,可安装、可离线。

## 部署到 GitHub Pages

1. 新建仓库(Public),把本文件夹里**所有文件**上传到根目录
2. Settings → Pages → Deploy from a branch → `main` / `/ (root)` → Save
3. 访问 `https://<用户名>.github.io/<仓库名>/`

> 注意:必须保持这个文件结构,`index.html`、`manifest.webmanifest`、`sw.js`
> 和图标要在同一层目录里,否则 Service Worker 注册不了。

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 程序本体,全部逻辑与样式 |
| `test/` | 端到端测试,不参与部署 |
| `manifest.webmanifest` | 应用名称、图标、启动方式 |
| `sw.js` | Service Worker,离线缓存 |
| `icon-*.png` `apple-touch-icon.png` `favicon-64.png` | 图标 |
| `design/` | 图标源文件和生成脚本,不参与部署 |

## 测试

```bash
npm install
npx playwright install chromium    # 只需一次
npm test
```

44 项端到端测试,用真实浏览器跑完整流程(导入 → 开奖 → 名单 → 导出 → 存档 → 恢复),
另外会真的关掉页面再打开,验证本机存档没丢。详见 [`test/README.md`](test/README.md)。

应用本身仍然是零构建的纯静态页面,`package.json` 和 `node_modules` 只服务于测试,
不影响部署。

## 改版本

改完 `index.html` 后,**两处版本号一起加一**:

1. `index.html` 里的 `APP_VERSION`(和 `APP_DATE`)
2. `sw.js` 第 3 行的 `VERSION`

不改 `sw.js` 的版本号,缓存不会刷新,用户收不到「有新版本」提示。
两处填的值不一样时,「设置 → 版本」那行会直接显示 `⚠ 离线缓存还是 vX`,
一眼就知道用户手上是不是旧缓存。

**换了图标还要再加一个**:图标 URL 后面的 `?r=N`,在 `index.html` 的 `<link>`、
`manifest.webmanifest` 的 `icons[].src`、`sw.js` 的 `ICON_REV` 三处,必须一起加一
且保持一致。浏览器是按 URL 缓存图标的 —— 尤其标签页上那个 favicon,同一个 URL
换了内容它未必会去重新拿。细节见 `design/README.md`。

`npm run test:assets` 会把上面这些全部核对一遍,不开浏览器,一秒出结果。

## 导入:每一列派什么用

导入文件后,会把表里的每一列列出来,逐列指定用途:**不用 / 姓名 / 副信息**。
选成「姓名」的列按文件里的先后**拼起来** —— 泰文名单常见「工号 | 称谓 | 名 | 姓」
分成四列,四列都要用上才能拼出完整的人名。只能二选一的话,总榜上会变成
大字是工号、小字是「นาย」,人名根本不出现。

工号那一行的字号跟着姓名一起缩放(约三分之一)—— 原来是固定 10-18px,
而姓名最大能到 104px,差了五六倍,投影上根本看不清工号。

默认会猜,两步:

1. **先看表头**(最准)。`COL_HINTS` 里按泰文 / 中文 / 英文的关键词分三类 ——
   部门、职位这类先排掉(默认「不用」),再认工号类,最后认姓名类。
   顺序不能反:「ชื่อแผนก(部门名称)」里也有「ชื่อ」,先匹配姓名的话会把部门拼进名字里。
2. 表头认不出来,再看这一列的内容:整列是纯数字/字母数字的归「副信息」,其余归「姓名」。

一份典型的泰文名单 `รหัสพนักงาน | คำนำหน้า | ชื่อ | นามสกุล | แผนก`,
导进去直接就是「นาย อร่าม จันพางาม」+ 工号 `01018`,部门自动排除,不用手动调。

猜错也不要紧 —— 确认按钮旁边有一张**按舞台样子画的预览卡**,选错列一眼就看出来。

## 名单搜索

名单面板有搜索框,按**姓名或工号**模糊匹配,命中的字段会标橙色。

两个容易踩的点:

- 列表最多只画 300 条(名单很大时开面板会卡),但**搜索是在全部人里找的**,
  不受这 300 条限制 —— 排在第 500 位的人照样搜得到。
- 每一行的 `idx` 直接记在数据上,不是靠「它排在列表第几位」倒推的。
  一搜索列表就被过滤了,倒推出来的位置全是错的,改名会改到别人头上。

## 结束画面

**每抽完一轮**,在揭晓那一屏点一次烟花,放几下自己收(放的下数跟中奖人数走,封顶 4 下)。
**全部抽完**后自动切到总榜,烟花持续放到离开这一屏。两种都是 canvas 实时绘制,不用任何库。
名字的 z-index 比烟花画布高,所以永远压在烟花上面,不会被挡住;画布
`pointer-events:none`,不挡按钮。离开总榜(撤销、重置、重新开抽)会立刻停掉,
不在后台烧 CPU。觉得花哨可以在「设置 → 配色主题」里关掉,开关记在本机。
系统开了「减少动态效果」时自动不放。

## 更新机制

**打开就自动更新**:开 App 的头 90 秒内如果发现新版本,直接装上并刷新,
用户什么都不用点,完成后提示「已更新到 vXX」。

**活动当中绝不自动刷新**。正在抽奖、正在揭晓、面板开着、粘贴框里有没提交的
名单 —— 这几种情况一律跳过,只亮出「有新版本」按钮,等用户自己挑时间点。

实现上有两条必须守住(`update` 和 `assets` 套件在盯):

1. **`sw.js` 的 `install` 里不能调 `skipWaiting()`。** 调了的话新版本装完就立刻
   接管并触发 `controllerchange`,页面那边的「现在能不能刷新」根本来不及判断。
   现在新版本老实等着,由页面 `postMessage('skip-waiting')` 决定什么时候换。
2. **判断「是不是更新」要用页面加载那一刻的 `hadController`**,不能用当前的
   `navigator.serviceWorker.controller` —— 第一次装 SW 时 `clients.claim()` 会让它
   当场非空,于是「第一次打开」被误判成「有新版本」,页面白白自己刷一次。

## 配色和 Logo

设置里有三套配色:**暖炭**(默认)、**年会红金**、**墨蓝**。三套都量过对比度,
正文都在 7:1 以上,投影上看得清。年会建议用红金 —— 喜庆,而且是三套里最高的。
不支持背景图,原因和加新主题的步骤见 `design/themes.md`。

Logo 换起来最快的办法是**直接点左上角那块**(没传过的话那里是「+ LOGO」按钮),
不用进设置。图片会自动缩到高 256px 再存,手机直接拍的大图也能传。
Logo 和主题都跟着本机存档走,换名单、清空名单都不会丢。

## 使用要点

- 抽奖顺序 = 奖项列表由上到下,最后一项压轴。前面没抽完后面锁住。
- 空格 = 开始/停止,F = 全屏,Esc = 关闭弹窗。
- 抽签用 `crypto.getRandomValues`,非 `Math.random`。取模偏差用拒绝采样消掉,
  所以名单里排第 1 和排第 200 的人概率严格相同,名单顺序对结果没有任何影响。
- 导入时会去掉**姓名和工号都一样**的重复行(同一个人出现两次,概率就翻倍了)。
  重名但没填工号的不敢替你删 —— 那可能真是两个人 —— 但会在名单面板里提醒你核对。
- **所见即所得**:按下停止时,定格在屏幕当前显示的那一组人,他们就是中奖者。
  每一帧本来就是随机抽的,同一帧内不会重复;一帧只停留 34–74 毫秒,远短于
  人的反应误差,卡不住任何人。
- 名单、Logo、奖项和已中奖名单会**自动存在本机浏览器里**(IndexedDB)。误关页面、
  断电、手机杀后台,重新打开自动接着上次继续,不用手动恢复。
- 数据只在本机,不上传。换设备或换浏览器不会同步 —— 那种情况用「设置 → 保存进度」
  导出 .json 带走,到新设备再「恢复进度」。
- 「设置 → 本机存档」里可以关掉自动保存,或一键清除本机数据(连名单和 Logo 一起删)。
- 第一次要联网打开一遍,缓存泰文字体和 Excel 解析库,之后才能完全离线。
- **导入格式**:Excel(.xlsx/.xls)、CSV/TXT、PDF,都会先弹列选择器让你指定
  「姓名列」和「副信息列」,确认预览无误再导入。
- 「名单」面板顶部会列出**当前名单**(待抽的在前,已中奖的打勾在后),
  每人后面有 ✎ 改名 / × 删除,还有「+ 添加一人」给临时到场的人用。
  已中奖的只能改名 —— 要删得先撤销那一轮或重置。
- **下次活动重新开始**:「名单 → 清空名单」一次清掉所有人和中奖结果,
  奖项设置和 Logo 保留,然后直接导入新名单。
- **PDF 只是保底方案**。PDF 没有表格结构,程序是按文字坐标反推行列的;
  更麻烦的是 PDF 的文字提取可能丢字 —— **泰文声调符号尤其容易丢**,取决于
  那个 PDF 是怎么生成的。名单重要的话请用 Excel 或 CSV。扫描件、拍照转的
  PDF 里根本没有文字层,读不出来,程序会明确提示。
- PDF 解析库(pdf.js)是**选中 PDF 文件时才去加载**的,平时不影响打开速度。
  第一次用 PDF 需要联网。
